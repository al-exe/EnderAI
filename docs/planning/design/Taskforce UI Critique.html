Taskforce — UI/UX critique
v1 · May 2026 · for @al-exe
Design review · web app + landing

The product is sharp. The UI is mostly lists.

Taskforce is doing something genuinely novel — turning agent work into reusable team memory with anchored evidence and a ROI ledger. But the UI today reads like a thin shadcn shell over four CRUD pages: a Library list, an Agents card grid, a KPI dashboard, and a landing page that says "Taskforce" without saying what it is. The visual system is fighting itself — --radius: 0 !important in CSS, rounded-[2rem] in the Agents page, rounded-lg on the landing. This document is a teardown plus two concrete redesign directions per surface, all anchored to your existing DNA: purple #8447ff, sharp corners, restrained type.

▍00 · System

What's broken at the system level

Before we touch any single screen, five system-level decisions need to be made. Most surface problems trace back to one of these — fix them once and four pages improve at the same time.

  1. The radius war

    Your index.css declares --radius: 0 !important — a strong, opinionated stance. But the Agents page renders rounded-[2rem] hero cards, the landing uses rounded-lg document tiles, shadcn primitives default to soft radii, and the result is a UI that can't decide whether it's brutalist or friendly. Commit one way. For your product (engineering tools, dense info, builder audience) sharp corners are the right call — but only if every surface honors it.

  2. Purple as decoration, not as signal

    Right now #8447ff shows up on primary buttons, sparkle icons, the marketing gradient — wherever a designer felt the page needed a bit of color. Promote purple to a semantic role: it means "this is Taskforce intelligence at work" — reuses, citations, replayed memory, AI-generated summary anchors. Strip it everywhere else. The product becomes legible the moment a single hue tells a story.

  3. The "team" promise is invisible

    The pitch — "engineering teams sharing context across people and machines" — is nowhere on the active screens. No avatars, no "who created this," no "@ana reused this 6× this week," no presence, no scope chip (mine / shared / org). For a tool whose main value is collaboration, every list row should declare its scope at a glance. This is the single biggest IA gap.

  4. Lists everywhere, hierarchy nowhere

    Library is a flat list. Agents is a flat grid. Metrics is a flat dashboard. There is no "first thing your eye lands on" anywhere. Every surface should have one hero artifact (the most-reused doc, the headline number, the top specialist) and then the long tail. "Boring lists" is your own description and it's accurate — flatness is the cause.

  5. The proof-of-value loop is hidden

    The most defensible thing Taskforce does is measure that reuse paid off. But savings only live on the Metrics page, walled off from where work happens. Surface "+38K saved on this reuse" inline — on Library rows, on Agent cards, in the document header, in the landing demo. Every encounter with a doc should re-anchor the user in why this tool exists.

  6. Type and density are inconsistent

    The Agents hero uses display-scale serifs; the Library uses small Geist body; Metrics KPIs use mid-weight numerals; chips are sometimes mono, sometimes sans. Lock a four-step type ramp (display / heading / body / mono-label), assign mono to data and identifiers only, and density becomes legible.

The design system, in one sentence

Sharp · Quiet · Loud where it matters.

Hairline borders everywhere. Zero radii. Generous whitespace. Geist sans for prose, JetBrains Mono for data and identifiers. One accent — purple — used only when Taskforce is doing the thing only Taskforce can do (reuse, replay, cite). One ink color for primary buttons. No decorative gradients. Numbers always tabular.

▍01 · Agents

Agents — currently the loudest, the least useful at a glance

Your own description: "Codex made this and it's not uniform with the rest." Agreed. The hero gradient, the rainbow card top-stripes, the 2rem rounded corners, the sparkle icons — none of it agrees with the brutalist DNA elsewhere. More importantly: a specialist gallery should answer one question, fast — which of these is paying for itself, and which is dead weight? The current grid buries that under decoration.

  • 3

The table is the right primary view for specialists — Engineers compare specialists like they compare CI runs. But B's dark stat strip is so good it should become a reusable component used on three surfaces. That gives you variety without inventing three different visual languages.

▍02 · Library

Library — the centerpiece, presented like a CRUD table

The Library is where the magic of Taskforce lives — every row represents a piece of working memory that may have just saved hours of agent context. Today it's rendered as a vanilla shadcn table: title, visibility, date. Three columns, none of which answer the question that matters: is this document paying off?

Problems today

  • 3
    Visibility ≠ team context
    "Organization" doesn't tell me who, when, or for what.
  • 4
    Folder structure as a flat sidebar
    No visual cue connecting a row to a folder once you click "All".
A · Minimal moves

    All / Mine / Shared / Org as a single row of underlined tabs. Sort dropdown on the right.
  • 2
    Reuse + saved as primary column
    14 · 142K saved tells the value story on every row.
  • 3
    Avatars + scope chip per row
    The "team" promise made visible inline.
B · Expressive moves
  • 1
    "Today" reel as a narrative
    Reuse moments rendered as sentences, not numbers. Recruits empathy.
  • 2
    Folder = colored side bar on card
    Color does the work the breadcrumb used to. Scannable from across the room.
  • 3

Document split view — the one explicit request

Make the single-document view readable in any window width.

Today the Summary / Details split breaks awkwardly under ~1100px. Switch to a resizable two-pane layout with three modes: summary (Summary fullwidth, Details collapsed to a citation popover), split (50/50 with anchored scroll-sync so clicking a §3 marker in Summary jumps Details to §3), details (Details fullwidth, Summary as a sticky outline on the left). The mode picker is one row of three icons. Persist per-document. Below ~900px collapse to a single column with a Summary/Details segmented toggle. This unblocks reading without re-architecting the page.

▍03 · Search

Search — the citations are the answer, not a footnote

The Search page today is a thin ChatGPT-shaped chat: messages stack, the LLM streams an answer, citations live as pill chips at the bottom like a research-paper bibliography. That's backwards for a "your work memory" tool. The citations are the product. The model is just narrating a path through your real documents — so the UI should make those documents present, not summarize and link off.

Problems today
  • 1
    BYOK pill, hidden in a sentence
    "Using your Anthropic key" lives inside body copy. Subtle but critical — should be a chip.
  • 2
    Citations divorced from claims
    All cites bunch at the bottom. The reader has to look up which one supports which sentence.
  • 3
    Token meta as a stray sentence
    "BYOK · model · 1,840 in / 220 out" reads like a stack trace, not a signal.
  • 4
    No conversation continuity
    Reload the page and the thread is gone. For a "memory" tool, that's the wrong default.
A · Minimal moves
  • 1
    Scope chips as the header
    "All docs · 28" / "org-shared · 4" / "recent · 7d" — answers "what am I asking?" at a glance.
  • 2
    Inline §-superscripts
    Each cite sits right where the claim ends. Hover preview; click to open the source.
  • 3
    Sources block with real section names
    "§3 — EU customer, no VAT" instead of #sec-eu-no-vat. Names not IDs.
B · Expressive moves
  • 1
    Thread rail — restore memory
    Grouped by today / yesterday / older. Each row shows cite count + tokens saved — the rail itself is a ledger.
  • 2
    "Reading…" status pip while streaming
    "Read 1 doc, 3 anchors · Stripe checkout wiring §1 §3 §5" — surfaces the work, not just the result.
  • 3
    "38K replayed from memory" chip
    Reuse loop, re-anchored at every turn. The tool earns its own existence on every screen.
  • 4
    Pinned citation drawer
    Click §3 → the actual section snippet appears in the right pane. No tab-switching, no doc-hunting.
Recommendation

Ship Direction A as a v1 polish; promote Direction B's pinned-citation pane to a system primitive.

The inline-superscript pattern from A is a one-week refactor — it'd transform how the page feels. The thread rail + pinned drawer from B is bigger work, but it's the same shape as the Document split view (Section 02). Build it once: a "right-pane citation viewer" that takes an anchor_id and renders that section. Reuse it in Search, in the document view, and in the in-app home's "Today reel". That's the same atom appearing three times — which is how a design system earns its keep.

Quietly important

The BYOK wall should be a progressive disclosure.

Today, no key = wall (a single Card with a key icon). Better: show the Search UI in a faded "preview" state, with the composer disabled and a single sentence at the input — "Add an Anthropic or OpenAI key to ask →". The user sees what they're missing before they're asked to pay for it. Same approach for the Upsell: show a few example threads from the team (already public) with results redacted; one CTA to upgrade. The current full-page Card feels like a paywall; the alternative feels like an empty pantry that's worth filling.

The current landing hero says "Taskforce" as the H1 and "AI work memory for builders" as the eyebrow — backwards. Visitors don't know what the product is yet; the brand name carries no weight. The preview card below shows a generic library, not a moment of the product earning its keep. There is no proof, no demo, no scope of who uses it.

    Right pane shows Cursor + Taskforce co-thinking with citations + savings stamp. No video needed.

Recommendation

Direction B for the marketing site; Direction A for the in-app landing (logged-in home).

The terminal demo earns its space when the audience is cold and skeptical. Once the user is logged in, they don't need a sales pitch — they need a quiet, dense number that says "your team saved X this week." Use both, not one.

▍06 · Rollout

If I were shipping this Monday

In order, smallest blast radius first. You can ship steps 1–3 in a week without touching backend.

01 · 1 day

Settle the radius war

Pick a stance globally. Strip rounded-* classes from V2/* components. Audit shadcn overrides.

02 · 1 day

Promote purple to a role

Define --tf-intel = #8447ff. Use only on reuse counts, citation links, replayed-context indicators.

03 · 2 days

Library rows, reshaped

Add Reuse · Owners · Saved columns. One filter bar. Folder = 4px side stripe. Direction A.

04 · 2 days

Agents page rebuild

Replace gradient hero + 2rem cards with the table + feature strip. Codex's work, retired.

05 · 2 days

Search citations inline

§-superscripts after each claim. Scope chips in the header. Sources block under each answer. One week to a different-feeling page.

06 · 3 days

Metrics narrative + dark strip

Billboard number, plain-English band, contributor leaderboard, methodology footnote.

07 · 3 days

Landing rewrite + live demo

New headline. Right-pane terminal showing Cursor + Taskforce mid-replay. Replace screenshot with proof.

08 · backlog

Right-pane citation primitive

One component, three places: Search thread, Document split view, in-app home Today reel. Shared right-rail that renders an anchor_id.

One last thing

Build the "reuse moment" as a primitive, not a feature.

Every screen in this critique benefits from the same atom — a short sentence saying "@alex reused Stripe checkout 2h ago — 38K saved · cited §3, §5". Build it once as <ReuseMoment>, render it in: the Library "Today" reel, the Agent card foot, the Metrics page, the document header, the in-app home, and the cold-pitch landing terminal. It's your product's smallest unit of value — make it a component, not a slide.
